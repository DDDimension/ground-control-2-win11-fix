# 操作步骤 · 读者版

> 这份文档是给**看帖子的用户**看的。
> 从零开始，照着做，15 分钟内能进游戏。

---

## 开始之前

| 项目 | 要求 |
|---|---|
| 系统 | Windows 10 / 11 |
| 显卡 | 支持 Vulkan（NVIDIA / AMD / Intel，2016 年之后的基本都行） |
| 游戏 | Steam 版 Ground Control II（AppID 254840） |
| 时间 | 约 15 分钟 |
| 需要改游戏本体吗 | **不需要，一个字节都不改** |

---

## 第 0 步：先确认你的症状对得上

符合以下任意一条，这个方案就是给你的：

- 点开始游戏后**黑屏卡死**，进程还在但界面不出来
- 听到 1 秒开场音效，然后什么都没有
- 进得去但屏幕上**全是竖条花屏**（彩虹色竖条纹）
- 画面**缩在左上角一块**，其余部分花屏
- **鼠标完全不能动**

如果症状是"游戏能玩只是有点卡"，那这个方案不对症，别装。

---

## 第 1 步：下载 DXVK

打开这个地址：

```
https://github.com/doitsujin/dxvk/releases
```

找到最新版本（比如 `v3.1.1`），在 **Assets** 里下载：

```
dxvk-3.1.1.tar.gz
```

> ⚠️ 注意是 `.tar.gz`，不是源码包（`Source code` 那两个）。
> Windows 上可以用 7-Zip 或 Bandizip 解压 `.tar.gz`。

**为什么不让本仓库直接给 DLL？**
因为 DXVK 是别人维护的开源项目，作者一直在更新。
从官方下最新版最稳妥，也符合开源社区的惯例。

---

## 第 2 步：解压，取 x32 里的两个文件

解压后你会看到这样的结构：

```
dxvk-3.1.1/
├── x32/          ← ★ 32 位，你要的是这个
│   ├── d3d9.dll          ← ★ 要这个
│   ├── dxgi.dll          ← ★ 要这个
│   ├── d3d8.dll          （不要）
│   ├── d3d10core.dll     （不要）
│   └── d3d11.dll         （不要）
└── x64/          （整 个文件夹不要）
```

**只取这两个**：

```
d3d9.dll
dxgi.dll
```

### 为什么必须是 `x32`？

Ground Control II 是 **2004 年的 32 位程序**。
`x64` 文件夹里的 DLL 是为 64 位程序准备的，放进 32 位游戏目录**不会被加载**，
游戏会继续用系统的老 DLL，症状照旧。

**这是最常见的错误，比什么都重要。**

### 为什么不能多复制几个？

有教程会让你把 `x32` 里的 DLL 全复制过去。**别这么做。**

- 这个游戏只用 D3D9，`d3d8.dll` / `d3d11.dll` 完全用不到
- `dxgi.dll` 是 DXVK 运行时需要配套的一个
- **多复制的文件 = 多一份卸载时要记着删的东西**

只要 `d3d9.dll` + `dxgi.dll` 两个。

---

## 第 3 步：找到游戏目录

### 方法 A：用 Steam（推荐）

1. 打开 Steam 库
2. 右键 **Ground Control II** → **管理** → **浏览本地文件**
3. 资源管理器会直接打开游戏目录

### 方法 B：默认路径

```
C:\Program Files (x86)\Steam\steamapps\common\Ground Control II
```

（如果你把 Steam 装在别的盘，把开头换成对应盘符）

### 怎么确认找对了

打开目录，应该能看到 **`gcii.exe`** 这个文件。

如果里面还有一层嵌套的同名文件夹，**进去那一层**，直到看见 `gcii.exe` 为止。

---

## 第 4 步：复制文件进去

把第 2 步取的 `d3d9.dll` 和 `dxgi.dll` **复制到和 `gcii.exe` 同一个文件夹**。

然后从本仓库下载 **`dxvk.conf`**，也放进同一个文件夹。

完成后目录长这样：

```
Ground Control II/
├── gcii.exe              ← 游戏主程序（原版，未改）
├── d3d9.dll              ← ★ 你新加的
├── dxgi.dll              ← ★ 你新加的
├── dxvk.conf             ← ★ 你新加的
├── gc2data.sdf           （原版）
├── gc2movies.sdf         （原版）
├── binkw32.dll           （原版）
├── mss32.dll             （原版）
└── ...                   （其他原版文件都没动）
```

> ✅ **只有 3 个新文件，其他全是你原来的。**

---

## 第 5 步：直接从 Steam 启动

**就点 Steam 里的「开始游戏」**，和平常一模一样。

❌ 不需要改启动选项
❌ 不需要加环境变量
❌ 不需要用额外的启动脚本
❌ 不需要改任何 Steam 设置
❌ 不需要改兼容性模式

**全部是文件级的，不碰你的系统和 Steam 配置。**

---

## 第 6 步：弹窗点「否」

启动时会跳出一个硬件检测的提示框（英文），大意是：

```
Your graphics card may not meet the requirements...
Gfx Vendor: nVidia, 0 Mb
Driver version: 32767.65535.65535.65535
DX9 driver: no
```

**点「否 / No / 取消 / Cancel」，然后继续。**

### 这个弹窗是什么？

这个 2004 年的游戏启动时会去注册表读**旧格式的硬件信息**，
而 DXVK 不会写这些老注册表项，所以游戏读到"显存 0 MB、没有 DX9 驱动"，就报警。

**它不影响游戏运行。** 实际画面由 DXVK → Vulkan → 你的显卡处理，性能完全正常。

### 能不能永久关掉？

很遗憾，不能"干净地"关掉。可行的办法只有两条：

1. 改游戏本体文件（**违背本方案原则，不做**）
2. 改系统环境变量或注册表（**会污染你的系统，不做**）

所以：**每次启动手动点一下「否」**。这是目前最干净的取舍。

## 第 7 步：验证成功

进游戏后，对着下面检查：

| # | 检查项 | 期望结果 |
|---|---|---|
| 1 | 能否进入游戏 | ✅ 主菜单正常出现 |
| 2 | 有没有竖条花屏 | ✅ 没有，画面干净 |
| 3 | 画面有没有铺满屏幕 | ✅ 铺满（不会被缩在左上角一块） |
| 4 | 鼠标能不能动 | ✅ 正常，可以点菜单 |
| 5 | 游戏内视频设置的分辨率列表 | ⚠️ 仍然是 5 项低分辨率（见下） |

**第 1~4 项全绿 = 修复成功。**

第 5 项修不了，原因见下一节。

## 关于分辨率：为什么下拉框还是 5 项低分辨率

这是**问得最多的问题**，先说清楚。

### 现象

游戏内「视频设置」的分辨率下拉框永远是这 5 项：

```
640x480
720x480
720x576
800x600
1024x768
```

### 原因

游戏代码**只读取分辨率列表的前 5 项**。
而 Windows 枚举分辨率是**按宽度从小往大**排的：

```
[0]  640x480     ← 第 1 项
[1]  720x480     ← 第 2 项
[2]  720x576     ← 第 3 项
[3]  800x600     ← 第 4 项
[4]  1024x768    ← 第 5 项
[5]  1152x864
...
[22] <你的原生分辨率>    ← 排在很后面，游戏永远读不到
```

也就是说，**不是 DXVK 没提供高分辨率，是游戏只肯看前 5 个**。

### 这是游戏引擎的硬限制

理论上可以用 DXVK 的 `forceAspectRatio` 把列表过滤到只剩 5 项，
让高分辨率落进前 5。但这个方案**必须配合 `DXVK_FORCE_WINDOWED` 环境变量**，
而环境变量在"从 Steam 直接启动"的路径下**注入不进去**。

（本项目的测试记录里，试过这条路，从 Steam 启动后立刻失效，
日志重新出现 `Buffer size: 199x34` 这种垃圾值，画面又缩回一块。）

**所以最终决定：接受这个限制，保证稳定。**
代价是游戏内显示 1024x768，
但**渲染区域是全屏的、画面会被拉伸铺满**，实际观感比"缩一块"好得多。

## 常见问题排查

### ❌ 还是黑屏卡死

**先查这两点：**

1. `d3d9.dll` 是否和 `gcii.exe` **在同一个文件夹**？（不是子文件夹里）
2. 是从 `x32` 还是 `x64` 拿的？（必须是 `x32`）

**确认没问题后：**

- 看看游戏目录里有没有生成 `gcii_d3d9.log`
  - **有** → DXVK 已接管，是配置问题
  - **没有** → DLL 没被加载，回到上面第 1、2 点

### ❌ 花屏（竖条）又回来了

改 `dxvk.conf` 里的这一行，改成**你显示器真实支持的最高刷新率**：

```ini
d3d9.forceRefreshRate = 300     ; ← 把 300 换成你自己的刷新率
```

**怎么查你的刷新率**：桌面右键 → 显示设置 → 高级显示 → 看「选择刷新率」下拉框的最大值。

比如你是 144Hz 显示器：

```ini
d3d9.forceRefreshRate = 144
```

**不要填一个你的显示器不支持的值。**

> 在部分硬件上，某些刷新率档位（尤其是 60Hz）会触发花屏。
> 如果某个值花屏，把显示器切到另一个刷新率档位，或换一根视频线试试。

### ❌ 鼠标还是不能动

1. 检查 `dxvk.conf` 里这一行存在且没被注释（行首没有 `#`）：

```ini
dxvk.enablePresentTiming = False
```

2. 确认文件名是**全小写**的 `dxvk.conf`（不是 `DXVK.conf` / `dxvk.conf.txt`）
3. 确认它在游戏目录里，和 `gcii.exe` 同级

> 小技巧：如果记事本给你存成了 `dxvk.conf.txt`，
> 在文件夹选项里打开"文件扩展名"显示，改回来。

### ❌ 画面还是缩在左上角一块

通常是文件没放对位置，或者 `dxvk.conf` 没生效。
用记事本的"另存为"重新保存一次 `dxvk.conf`（编码选 **UTF-8**），确保是纯文本。

### ❌ Steam 提示游戏在运行，但什么都没有

任务管理器里结束 `gcii.exe` 进程，再重试。

## 怎么卸载（完全还原）

删掉这 3 个文件：

```
d3d9.dll
dxgi.dll
dxvk.conf
```

游戏立刻回到**原始状态**（也就是：在你的新电脑上黑屏卡死）。

### 想彻底验证没改过游戏？

用 Steam 官方校验：

**Steam 库 → 右键 Ground Control II → 属性 → 已安装文件 → 验证游戏文件的完整性**

结果会是 **全部通过** —— 因为游戏本体文件从来没被修改过。

---

## 原理（一句话）

Windows 加载 DLL 的顺序是：

```
程序自己的目录  →  系统目录  →  PATH
```

游戏调用 `d3d9.dll` 时，Windows **优先用游戏目录里的那一份**。
所以我们只需把 DXVK 的 `d3d9.dll` 放进去，
游戏就自动从"用微软的老实现"变成"用 DXVK 的现代实现"，
而游戏自己完全不知道。

**没有打补丁、没有改二进制、没有 hex 编辑。**
