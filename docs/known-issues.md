## 二、实测日志证据

修复成功后，游戏目录会生成 `gcii_d3d9.log`。关键几行：

### 设备识别正确

```
info:  DXVK: v3.1.1
info:  Found config file: dxvk.conf
info:    d3d9.forceRefreshRate = 300
info:    dxvk.enablePresentTiming = False
info:  Found device: <你的显卡型号> (驱动的渲染器版本)
info:    Heap 0: <显存大小> GiB (DEVICE_LOCAL)
```

→ 正确选中独显，显存识别正常（**修复前卡死在这一步之前**）。

> 把 `Found device:` 后面那行换成**你自己日志里的那一行**即可。
> 这一行证明 DXVK 已经接管 D3D9 并选中了正确的显卡。

### 交换链尺寸正确（这是"画面铺满"的直接证据）

```
info:  D3D9DeviceEx::ResetSwapChain:
info:    Requested Presentation Parameters
info:      - Width:              1024
info:      - Height:             768
info:      - Windowed:           false
info:  Setting display mode: 1024x768@300
info:  Setting display mode: 1024x768@300
info:  Presenter: Actual swapchain properties:
info:    Buffer size:  1024x768        ← ✅ 与请求一致
info:  Restoring display mode: 2560x1440@300
```

> 上面 `Restoring display mode:` 那一行的分辨率会是你自己显示器的原生分辨率。

**关键点**：`Buffer size` 必须有且只有一次，且与 `Requested` 的 `Width` / `Height` 一致。

### 失败时的指纹：`199x34`

在失败版本的日志里会出现：

```
info:    Buffer size:  199x34      ← ❌ 这个垃圾值就是"缩一块 + 鼠标错乱"的指纹
```

`199x34` 来自"窗口尚未建立完成时的 `GetClientRect`"。
**它一出现，画面必然缩一块、鼠标必然错乱。**
所以判断修复是否生效，**直接搜日志里有没有 `199x34`** 是最快的办法。

## 三、已知限制（如实说明）

### 限制 1：游戏内分辨率只有 5 项低分辨率

**现象**：视频设置里的下拉框永远是：

```
640x480 · 720x480 · 720x576 · 800x600 · 1024x768
```

**原因**：游戏代码只读取枚举列表的**前 5 项**，
而 Windows 的枚举顺序是**按宽度升序**：

```
[ 0] 640x480
[ 1] 720x480
[ 2] 720x576
[ 3] 800x600
[ 4] 1024x768     ← 游戏能看到的最后一项
[ 5] 1152x864
 ...
[22] <你的原生分辨率>    ← 排在很后面，游戏永远读不到
```

**这是游戏引擎硬编码的行为，不是 DXVK 配置问题。**

**尝试过的方案**：用 `d3d9.forceAspectRatio = "16:9"` 把列表过滤到恰好 5 项
（实测会得到 `1280x720 / 1366x768 / 1600x900 / 1920x1080 / 2560x1440`，
高分辨率正好落在第 5 项）。

**为什么放弃**：该方案必须配合 `DXVK_FORCE_WINDOWED` 环境变量才能保证画面不缩一块，
而**从 Steam 直接启动时环境变量注入不进去**。
实测从 Steam 启动后立即失效，画面退回"缩一块 + 鼠标错乱"。

**取舍**：稳定性优先。接受下拉框显示低分辨率，
**但渲染区域是全屏的**，画面会被拉伸铺满显示器，观感远好于"缩一块"。

**如果你愿意使用启动脚本**（不推荐普通用户）：可以用 `DXVK_FORCE_WINDOWED=1`
配合 `forceAspectRatio` 拿到高分辨率选项，代价是必须用脚本启动、不能直接点 Steam。
本项目不推荐这条路，因为它和"从 Steam 点开始游戏"的日常习惯冲突。

### 限制 2：启动时的硬件检测弹窗

**现象**：每次启动弹一次英文警告框：

```
Gfx Vendor: nVidia, 0 Mb
Driver version: 32767.65535.65535.65535
DX9 driver: no
```

**原因**：游戏启动时去**注册表读旧格式的硬件信息**。
DXVK 不做老式注册表写入，游戏读到的是"显存 0MB、无 DX9 驱动"，于是误判报警。

**影响**：**完全不影响运行**。图形由 DXVK → Vulkan 处理。
点「否 / No / Cancel」即可正常进入。

**为什么不能关掉**：
- 改游戏本体文件 → 违背本方案"零改动"原则
- 改注册表 / 环境变量 → 污染系统

**结论**：每次手动点一下「否」，这是最干净的取舍。

### 限制 3：`forceRefreshRate` 需要按你的显示器改

`dxvk.conf` 里是 `d3d9.forceRefreshRate = 300`，**是针对 300Hz 显示器调的示例值**。

它有两个作用：

1. **让游戏请求高分辨率** —— 高刷新率只存在于显示器的原生模式上，
   过滤后唯一的高分辨率就是它
2. **避免掉到花屏档位** —— 在某些硬件上，60Hz 正是花屏的触发档位

**必须先查出你自己显示器的最高刷新率**，然后改成对应的值：

```ini
d3d9.forceRefreshRate = 144     ; 144Hz 显示器
d3d9.forceRefreshRate = 165     ; 165Hz 显示器
d3d9.forceRefreshRate = 240     ; 240Hz 显示器
```

**不要留一个你的显示器不支持的值。** 怎么查见 `07-通用化改造指南-含提示词.md` 第一部分。

## 六、附：如何验证真的修好了

启动游戏后，游戏目录会生成 `gcii_d3d9.log`。**这是最可靠的验证依据**：

| 在日志里搜 | 期望结果 | 含义 |
|---|---|---|
| `Found config file: dxvk.conf` | 有，且下面列出你的配置项 | 配置被正确读取 |
| `Found device:` | 显示你的显卡型号 | 显卡识别正确 |
| `Buffer size:` | **只有一次**，且与 `Requested` 的宽高一致 | ★ 画面正确铺满 |
| `199x34` | **搜不到** | ★ 这是"缩一块 + 鼠标错乱"的指纹，搜到即失败 |

**`199x34` 是最快的诊断指标。**
它来自"窗口尚未建立完成时的 `GetClientRect`"——
一旦出现，画面必然缩一块、鼠标必然错乱。**搜不到它 = 画面正常。**
